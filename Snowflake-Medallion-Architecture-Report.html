Snowflake Project

Snowflake Medallion Data Warehouse Architecture

Repository: MuhammadHuzaifaG/Snowflake-Medallion-Data-Warehouse-Architecture

Project Overview

This project implements a multi-layer Medallion Data Warehouse architecture (Bronze, Silver, and Gold) built on Snowflake to ingest, clean, model, and analyze retail e-commerce datasets. The architecture is designed to support data quality, traceability, and high-performance analytical querying across enterprise retail operations.

Business Problem & Core Challenge

Modern enterprise retail systems generate raw transactional data across decoupled sources. Uncleaned records, dynamic formats, and missing relationships make it difficult to build a reliable, analytics-ready data platform. This project addresses those challenges by standardizing ingestion and transformation practices while ensuring clean, business-friendly reporting models.

Data Pipeline Architecture

[ Raw Batch Data ]
    │
    ▼
[ BRONZE SCHEMA ] ──> Raw Stage & Stream Buffering
    │
    ▼
[ SILVER SCHEMA ] ──> Cleansed Entities (Customers, Products, Stores, Employees, Orders)
    │
    ▼
[ GOLD SCHEMA   ] ──> Dimensional Modeling (DIM_CUSTOMER, DIM_PRODUCT, DIM_STORE, DIM_DATE, FACT_SALES)

Technical Stack

  • Cloud Data Platform: Snowflake
  • Compute Management: COMPUTE_WH (Auto-Suspending X-Small Virtual Warehouse)
  • Data Modeling: Dimensional Star Schema Modeling (Kimball Methodology)
  • Language: SQL (Snowflake dialect)
  • Ingestion & Transformation: Batch INSERT INTO, TRUNCATE / LOAD, window aggregations

Layer-by-Layer Implementation

1. Database & Schema Initialization

The project creates the main database and segregates logical processing areas:

CREATE DATABASE IF NOT EXISTS SNOWFLAKE_DB; USE DATABASE SNOWFLAKE_DB; CREATE SCHEMA IF NOT EXISTS BRONZE_LANDING; CREATE SCHEMA IF NOT EXISTS SILVER_TRANSFORMED; CREATE SCHEMA IF NOT EXISTS GOLD_DATAMART;

2. Bronze Layer

Acts as a landing area for raw incoming data and preserves the original structured records before validation.

3. Silver Layer

Establishes cleaned relational tables with strict typing, nullability rules, and domain integrity.

  • Customers
  • Products
  • Stores
  • Employees
  • Orders

4. Gold Layer

Transforms normalized relational tables into a star schema optimized for BI and analytical consumption.

  • DIM_CUSTOMER
  • DIM_PRODUCT
  • DIM_STORE
  • DIM_DATE
  • FACT_SALES

Key Analytics & Business Outcomes

  1. Category Performance: Electronics is the largest revenue driver; Home & Kitchen has the highest transaction velocity.
  2. Geographic Distribution: Major metro states such as NY, CA, and IL account for a significant share of sales.
  3. Pipeline Efficiency: Set-based SQL transformations reduce warehouse runtime while maintaining traceability.

What Was Learned

  • Schema design in Snowflake and metadata optimization
  • Dimensional modeling with surrogate keys and date-spine generation
  • ELT best practices using layer isolation and bulk processing

Example Query: Category Performance

SELECT dp.CATEGORY AS "Product Category", COUNT(DISTINCT fs.ORDER_ID) AS "Total Orders", SUM(fs.QUANTITY) AS "Units Sold", ROUND(SUM(fs.GROSS_REVENUE), 2) AS "Total Revenue" FROM GOLD_DATAMART.FACT_SALES fs JOIN GOLD_DATAMART.DIM_PRODUCT dp ON fs.PRODUCT_KEY = dp.PRODUCT_KEY WHERE fs.STATUS IN ('COMPLETED', 'DELIVERED', 'SHIPPED') GROUP BY dp.CATEGORY ORDER BY "Total Revenue" DESC;

Example Query: Daily Revenue Trend

SELECT dd.FULL_DATE AS "Date", dd.DAY_OF_WEEK AS "Day", COUNT(DISTINCT fs.ORDER_ID) AS "Total Orders", ROUND(SUM(fs.GROSS_REVENUE), 2) AS "Daily Revenue" FROM GOLD_DATAMART.FACT_SALES fs JOIN GOLD_DATAMART.DIM_DATE dd ON fs.DATE_KEY = dd.DATE_KEY WHERE fs.STATUS IN ('COMPLETED', 'DELIVERED', 'SHIPPED') GROUP BY dd.FULL_DATE, dd.DAY_OF_WEEK ORDER BY dd.FULL_DATE ASC;
